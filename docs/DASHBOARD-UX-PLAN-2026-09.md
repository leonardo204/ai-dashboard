- 작성일: 2026-09-09
- 근거 문서: [DASHBOARD-UX-REVIEW-2026-09.md](DASHBOARD-UX-REVIEW-2026-09.md) (진단·업계 기준·방향 A~G)
- 대상 코드: `src/ui.ts`(틀·스타일·차트), `src/views.ts`(화면 본문), `src/stats.ts`(집계), `src/index.ts`(라우팅)
- 용도: 구현 세션에 그대로 건네는 작업 지시서입니다. 태스크 하나가 커밋 하나입니다.

## 1. 전체 구조

| 단계 | 태스크 | 목표 |

## 2. 실행 규칙

구현 세션이 지켜야 할 것입니다.

- 시작 전에 이 문서와 `docs/UI-RULES.md`(T1에서 만듦)를 읽습니다.
- 태스크 하나 = 커밋 하나. 커밋 제목은 기존 방식대로 한국어 한 줄입니다(예: `상황판 — 상태 한 줄과 지표 카드 4개`).
- 커밋 전에 `npm run typecheck`와 `npm run dry-run`을 통과합니다.
- 화면이 바뀌는 태스크는 배포(`npm run deploy`) 후 운영 주소에서 확인합니다. 확인 방법은 각 태스크의 "확인" 항목입니다. 로그인은 `/admin/login`에 폼 POST(`.dev.vars`의 ADMIN_USER·ADMIN_PASS)로 세션 쿠키를 받아 curl로 HTML을 받습니다.
- 확인은 노트북 폭(1280px)과 휴대폰 폭(390px) 둘 다 봅니다. 브라우저가 없으면 HTML 구조와 CSS 미디어 쿼리로 대신 검토하고 그 사실을 보고에 적습니다.
- `/admin/api/*` 경로는 건드리지 않습니다. 이상탐지 서버(ai-service)와 각 서비스의 트래픽 전송이 이 경로를 씁니다.
- 새 색·글자 크기·반경 값을 추가하지 않습니다. 필요하면 `UI-RULES.md`를 먼저 고치고 그 이유를 커밋에 적습니다.
- 화면 문구 어미는 "~어요"입니다.
- 태스크마다 끝나면 무엇을 바꿨고 무엇을 확인했는지 짧게 보고합니다. 마일스톤이 끝나면 4장의 검수표로 최종 보고합니다.
- 코드 주석은 "왜"를 적습니다. 지금 코드의 주석 방식을 따릅니다.

## 3. 태스크

각 태스크는 목적 · 파일 · 세부 작업 · 완료 기준 · 확인 · 의존 순입니다. 크기는 소(반나절 이내)·중(하루)·대(이틀 이상)입니다.

### M1 — 화면 규칙과 뼈대

#### T1. 화면 규칙 문서 `docs/UI-RULES.md` (소)

- 목적: 이후 모든 태스크가 참조할 기준을 한 장에 적습니다.
- 파일: `docs/UI-RULES.md` (신규)
- 세부 작업
  - 색 토큰 12개와 뜻: 바탕 2(`--bg`, `--panel`) · 글자 3(`--ink`, `--ink-2`, `--muted`) · 선 1(`--line`) · 강조 1(`--accent`) · 상태 3(`--ok`, `--warn`, `--bad`) · 데이터 계열 2(`--svc` 서비스, `--int` 내부 도구). 상태색의 흐린 배경이 필요하면 `color-mix()`로 만들고 새 값을 두지 않습니다.
  - 글자 크기 5단계: `--fs-xs 11px`(축 눈금·각주) · `--fs-sm 12.5px`(표·보조) · `--fs-md 14px`(본문) · `--fs-lg 18px`(제목) · `--fs-xl 28px`(지표 숫자). 굵기는 400·600·700 세 가지.
  - 모서리 반경 3종: `--r-sm 6px`(태그·입력·작은 막대) · `--r-md 12px`(카드·표·그래프 판) · `--r-pill 999px`.
  - 간격 4단계: 4 · 8 · 12 · 20px.
  - 구성요소 규칙: 소제목은 `sectionHead()` 하나. 지표 카드는 `kpiCard()` 하나(이름표·숫자·비교·추이선, 크기 옵션 `lg|sm`). 각주는 화면당 한 줄 이하, 나머지는 소제목 옆 ⓘ 툴팁.
  - 그래프 규칙: 값 비교는 막대(가로 막대 우선), 흐름은 꺾은선. 도넛·파이 금지. 색은 서비스=`--accent`, 내부 도구=`--int`(회색), 실패=`--bad`. 빨강은 실패·문제 상태에만.
  - 상태 표기: 정상·주의·문제 세 단계. 판단 기준은 T9에 적힌 것을 옮겨 적습니다.
  - 문구: 어미 "~어요", 숫자는 `toLocaleString()`, 비용은 `usd()`, 시각은 KST.
- 완료 기준: 위 항목이 모두 표로 정리되어 있고, 현재 값 → 새 값 대응표(T2에서 쓸 것)가 붙어 있습니다.
- 확인: 문서 검토만.
- 의존: 없음.

#### T2. 토큰 도입과 값 치환 (대)

- 목적: 색 91종·글자 17단계·반경 16종을 T1 토큰으로 바꿉니다.
- 파일: `src/ui.ts` (`:root` 16행, `ADMIN_CSS` 전체, SVG 차트의 색 문자열), `src/views.ts`(인라인 style 색이 있으면)
- 세부 작업
  1. 현황 목록을 뽑아 `docs/UI-RULES.md` 대응표에 붙입니다. 명령: `grep -oE '#[0-9a-fA-F]{3,6}\b' src/ui.ts | sort | uniq -c | sort -rn`, `grep -oE 'font-size:[0-9.]+px'`, `grep -oE 'border-radius:[0-9]+px'`.
  2. `:root`에 토큰 12개 + 글자 5개 + 반경 3개 + 간격 4개를 정의합니다. 기존 `--g`, `--r`는 `--ok`, `--bad`로 이름을 바꾸고 참조를 모두 고칩니다.
  3. 색 리터럴을 대응표대로 토큰으로 치환합니다. 같은 뜻인데 다른 색(예: 실패 `#e2686b`, `#c0392b`, `#a9313a`, `#d1495b`)은 하나로 합칩니다. 흐린 배경(`#fdecec` 등)은 `color-mix(in srgb, var(--bad) 12%, white)`로 바꿉니다.
  4. 글자 크기를 5단계로 올림·내림합니다. 11.5→11, 12→12.5, 13·13.5→14, 15~20→18, 24·32→28. 표 안 글자는 12.5, 본문 14.
  5. 반경을 3종으로 바꿉니다. 3·4·5→6, 7~16·18·20→12, 999는 그대로.
  6. SVG 차트(`svgTrend`, `svgLevels`, `svgHeat`, `svgDonut`, 지도)의 색 문자열은 CSS 클래스로 옮겨 토큰을 씁니다. 지도 육지색 같은 장식색은 `--line`·`--muted`로 대체합니다.
  7. 다크 모드가 없으므로 다루지 않습니다.
- 완료 기준
  - `:root` 밖의 16진수 색 리터럴 0개(SVG 포함).
  - `font-size` 값 집합이 토큰 5개뿐.
  - `border-radius` 값 집합이 토큰 3개뿐.
- 확인: 위 grep 명령을 다시 돌려 개수를 보고에 붙입니다. 배포 후 요약·이상탐지·트래픽·로그 네 화면을 열어 깨진 곳(글자 넘침, 표 폭, 툴팁)이 없는지 봅니다.
- 의존: T1.

#### T3. 소제목 한 방식으로 통일 (소)

- 목적: `sectionHead()` 35곳과 `<div class="sh2">` 12곳을 하나로 합칩니다.
- 파일: `src/ui.ts`(`sectionHead` 1609행), `src/views.ts`(sh2 12곳: 212·314·317·320·365·374·377·449·459·464·1510·2266행 부근)
- 세부 작업
  - `sectionHead(title, opts?)`로 시그니처를 바꿉니다. `opts = { href?, linkLabel?, count?, note?, tip?, id?, right? }`. `count`는 제목 옆 회색 숫자, `note`는 오른쪽 작은 글씨(지금 `.sm`), `tip`은 ⓘ 툴팁 문구(T5에서 씀), `right`는 필터 입력 같은 임의 HTML.
  - sh2 12곳을 새 `sectionHead()`로 바꿉니다. `tableFilter()`를 오른쪽에 두던 곳은 `right`로 넣습니다.
  - `.sh2` CSS를 지웁니다.
- 완료 기준: `grep -c 'class="sh2"' src/views.ts` = 0. CSS에 `.sh2` 없음.
- 확인: 배포 후 사용량·추이·지역·이상탐지·트래픽 화면 소제목의 모양·간격이 같음.
- 의존: T2.

#### T4. 지표 카드 구성요소 하나로 (중)

- 목적: 큰 카드(`.k1`)와 작은 카드(`mini()`)를 `kpiCard()` 하나로 합칩니다. T10 상황판이 이것을 그대로 씁니다.
- 파일: `src/ui.ts`(신규 `kpiCard()`, `.k1`·`.kpi2`·`mini` 정리), `src/views.ts`(요약 화면 카드 3개 + 작은 카드 6개)
- 세부 작업
  - `kpiCard({ label, value, unit?, delta?: { cur, prev, higherIsWorse }, sub?, spark?: number[], size?: "lg"|"sm", tone?: "ok"|"warn"|"bad" })`.
  - 추이선은 `sparkline(values)` 함수로 분리해 카드 밖에서도 씁니다(지금 요약 카드의 spark 코드를 옮김).
  - 숫자는 `font-variant-numeric: tabular-nums`.
  - 요약 화면의 카드 3개를 `kpiCard(size:"lg")`로, 작은 카드 6개는 이번 태스크에서는 `size:"sm"`으로 바꿔 두고 T10에서 뺍니다.
- 완료 기준: `mini()` 함수와 `.k1`·`.kpi2` 클래스가 사라지고 `kpiCard()`만 남음.
- 확인: 배포 후 요약 화면 카드 모양이 이전과 같거나 정돈됨. 휴대폰 폭에서 카드가 한 줄씩 쌓임.
- 의존: T2.

#### T5. 각주 정리 (소)

- 목적: 각주 문단 11개를 화면당 한 줄 이하로 줄이고 나머지는 툴팁으로 옮깁니다.
- 파일: `src/views.ts`(`class="foot"` 11곳, `FOOT_GEO`·`FOOT_COST` 58~60행), `src/ui.ts`(ⓘ 아이콘 스타일)
- 세부 작업
  - 각 각주 문장을 셋으로 분류합니다. (a) 그 칸에만 해당 → 해당 `sectionHead(tip:)`으로. (b) 화면 전체 해당(예: "구간은 KST 기준") → T15 상단 상태줄로 옮길 후보로 표시하고 지금은 한 줄 각주로 남김. (c) 설명서 성격(비용 추정 방식, 내부용 앱 뜻) → 가이드 문서(`docs/PROXY-CLIENT-GUIDE.md` 또는 README)에 넣고 각주에서는 링크 한 개.
  - `data-tip` 툴팁 기능이 이미 있으므로 ⓘ는 `<span class="info" data-tip="...">ⓘ</span>`로 만듭니다.
- 완료 기준: 화면마다 `.foot`가 0~1개, 한 줄(80자 이내).
- 확인: `grep -c 'class="foot"' src/views.ts` ≤ 화면 수(10). 각주 내용이 사라진 게 아니라 툴팁·문서로 옮겨졌는지 대조표를 보고에 붙입니다.
- 의존: T3.

#### T6. 탭 9개 → 5개, 하위 탭과 새 주소 (대)

- 목적: 상단 탭을 상황판 / AI 호출 / 트래픽 / 이상탐지 / 설정으로 묶고 하위 탭을 둡니다.
- 파일: `src/index.ts`(라우팅 282~700행), `src/ui.ts`(`NAV` 1474행, `TabKey`, `shellAdmin`, 신규 `subTabs()`), `src/views.ts`(각 render의 `tab` 옵션), `README.md`, `docs/PROXY-API.md`
- 새 주소 체계

  | 탭 | 주소 | 하위 탭 | 지금 주소 |
  | --- | --- | --- | --- |
  | 상황판 | `/admin` | 없음 | `/admin` |
  | AI 호출 | `/admin/calls` | 흐름 `/admin/calls`(기본) · 나눠 보기 `/admin/calls/usage` · 지역 `/admin/calls/geo` · 로그 `/admin/calls/logs` | `/admin/trend`, `/admin/usage`, `/admin/geo`, `/admin/logs` |
  | 트래픽 | `/admin/traffic` | 방문 `/admin/traffic`(기본) · 크롤러 `/admin/traffic/bots` · 경로 `/admin/traffic/paths` | `/admin/traffic` 한 화면 |
  | 이상탐지 | `/admin/anomaly` | 받은 신호 `/admin/anomaly`(기본) · 탐지기 상태 `/admin/anomaly/detector` · 메일 `/admin/anomaly/mails` | `/admin/anomaly`, `/admin/anomaly/mail/...` |
  | 설정 | `/admin/settings` | 앱 관리 `/admin/settings/apps`(기본) · 연결 가이드 `/admin/settings/guide` | `/admin/apps`, `/admin/guide` |

- 세부 작업
  1. `TabKey`를 `board | calls | traffic | anomaly | settings`로 바꾸고 `NAV`를 5개로 줄입니다. `shellAdmin` 옵션에 `sub?: { key, items }`를 추가해 상단 탭 아래에 하위 탭 줄을 그립니다. 하위 탭은 기간·앱 필터와 한 줄에 둡니다(왼쪽 하위 탭, 오른쪽 필터).
  2. `index.ts`에 새 경로를 추가하고 옛 경로는 301로 새 경로에 보냅니다(쿼리 문자열 유지). `/admin/logs.csv`, `/admin/stats.json`, `/admin/guide.md`는 그대로 둡니다(다른 곳에서 링크할 수 있음). `/admin/anomaly/<id>` 상세와 `/admin/anomaly/mail/<id>`는 그대로 둡니다.
  3. 이번 태스크에서는 화면 본문을 옮기지 않습니다. 트래픽 하위 탭 3개는 지금 트래픽 화면의 11칸을 방문(방문 추이·종류·서비스별·서비스 요약) / 크롤러(AI 크롤러·검색 크롤러·읽어간 경로·최근 크롤러 방문) / 경로(유입 경로·많이 열린 경로·404)로 나누기만 합니다. `collectTraffic`은 그대로 쓰되 각 하위 탭이 필요한 것만 그리도록 render 함수를 셋으로 나눕니다.
  4. 이상탐지 하위 탭은 이번에는 주소만 만들고 화면 분리는 T12에서 합니다(`/admin/anomaly/detector`는 T12 전까지 `/admin/anomaly#detector`로 보냄).
  5. README 엔드포인트 표와 `docs/PROXY-API.md`의 관리 화면 주소를 갱신하고 `npm run gen:guide`를 돌립니다.
  6. 화면 안의 링크(`sectionHead` href, 요약의 "자세히 →", 로그 필터 링크, 이상탐지 상세의 돌아가기)를 전부 새 주소로 바꿉니다. 옛 주소 리다이렉트에 기대지 않습니다.
- 완료 기준
  - 상단 탭 5개, 각 하위 탭이 위 표대로 열림.
  - 옛 주소 9개가 모두 301로 새 주소에 도착(쿼리 유지).
  - 코드 안에 옛 주소 문자열이 남아 있지 않음(`grep -nE '"/admin/(trend|usage|geo|logs|apps|guide)"' src` = 0, `.csv`·`.md`·`.json` 제외).
- 확인: curl로 옛 주소 9개의 상태 코드와 Location을 표로 보고. 새 주소 전부 200. 휴대폰 폭에서 하위 탭이 줄바꿈 없이 가로 스크롤되는지 확인.
- 의존: T3.

#### T7. 기간 탭 6개 → 4개 (소)

- 목적: 주·월·분기·반기·년·전체를 7일·30일·90일·전체로 줄입니다.
- 파일: `src/stats.ts`(`PERIODS` 518행), `src/ui.ts`(`filterTabs`), `src/index.ts`(period 파싱)
- 세부 작업
  - `PERIODS`에서 `half`, `year`를 지웁니다. 라벨은 "7일 · 30일 · 90일 · 전체".
  - 옛 값이 쿼리로 오면 `half → quarter`, `year → all`로 바꿔 처리합니다(리다이렉트 없이 내부 매핑).

#### T9. 상황판 집계 `collectBoard()` (중)

- 목적: 첫 화면에 필요한 것만 쿼리 6개 안쪽으로 가져옵니다. 지금 `collectSummary`는 14개를 냅니다.

- 가져올 것과 쿼리

  | # | 내용 | 쿼리 |
  | --- | --- | --- |
  | 1 | 이번 기간 앱·모델별 집계(호출·성공·실패·토큰·비용·지연 합) | `calls` GROUP BY app, model (지금 `grouped`) |

  | 7 | 트래픽 한 줄(오늘 방문·AI 크롤러 비중) | `hits` 하루치 집계 1회 |

  1. 문제: 열린 critical 신호가 있음 / 이상탐지 서버 신호가 15분 넘게 없음 / 이번 기간 실패율 ≥ 5% (호출 20건 이상일 때만)
  2. 주의: 열린 warn 신호가 있음 / 서버 신호 5~15분 지연 / 실패율이 직전 기간의 3배 이상(그리고 ≥ 1%) / 이달 예상 비용이 지난달의 1.5배 초과(월 진행률 15% 이상일 때만) / p95가 직전 기간의 2배 이상(호출 20건 이상)

  - 서버 상태는 `anomaly_state`의 heartbeat 하나만 읽습니다(`shellAdmin`에 `opts.heartbeatAge`로 전달, 각 collect가 이미 읽는 값을 넘김).
  - `pageHead`의 시계와 이상탐지 화면의 `serverBar`, 각주의 KST 문장을 지웁니다.
  - 로그 화면처럼 자동 갱신이 꺼진 화면은 "자동 갱신 끔(이 화면)"으로 표시.
- 완료 기준: 서버 상태·자동 갱신·KST 표시가 코드 한곳(`shellAdmin`)에만 있음.
- 확인: 배포 후 모든 화면 상단에 같은 줄. 자동 갱신 토글이 그 줄에서 동작.
- 의존: T13.

#### T16. 도넛 → 가로 막대 (소)

- 목적: 도넛 4곳 이상(앱·모델 비중, 심각도, 방문 종류, `smallDonut` 3곳)을 가로 막대로 바꿉니다.
- 파일: `src/ui.ts`(`svgDonut`·`donutTip` 삭제, 신규 `hbars(items, opts)`), `src/views.ts`(115·124·969·1277·2065·2312행 부근)
- 세부 작업
  - `hbars({ label, value, sub? }[], { unit, max?, top?: 8 })`: 이름 · 막대 · 값 · 비율. 상위 8개 + "그 외". 색은 `--accent` 하나, 내부 도구 항목만 `--int`, 심각도는 `--bad`·`--warn`·`--muted`.
  - `.donut` 관련 CSS 삭제.
- 완료 기준: `grep -c 'onut' src` = 0.
- 확인: 배포 후 나눠 보기·탐지기 상태·트래픽 방문 탭에서 막대 표시와 툴팁 확인.
- 의존: T12.

#### T17. 그래프 위 이상 구간 표시와 기여 보기 (중)

- 목적: 받은 신호 화면의 신호 그래프와 AI 호출 흐름 그래프에 이상 구간을 색 띠로 표시하고, 띠를 누르면 그 구간의 앱·모델별 기여를 보여줍니다(Watchdog 방식).
- 파일: `src/ui.ts`(`svgTrend`에 `marks?: { from, to, level }[]` 옵션), `src/stats.ts`(구간별 앱·모델 집계 쿼리 1개: `?bucket=`), `src/index.ts`(`/admin/api/bucket-breakdown` 또는 상세 화면 안에 포함), `src/views.ts`
- 세부 작업
  - 흐름 그래프의 버킷 중 `anomalies.bucket`과 겹치는 것에 반투명 띠(`--warn`·`--bad` 12%).
  - 띠 클릭 → 신호 상세(`/admin/anomaly/<id>`)로 이동하고, 상세 화면 안에 "이 구간에서 많이 부른 앱·모델" 가로 막대(`hbars`)를 추가합니다. 새 API 없이 상세 화면 집계에 쿼리 1개를 더하는 쪽이 단순합니다.
- 완료 기준: 이상이 있는 기간에서 띠가 보이고, 상세 화면에서 기여 막대가 실제 집계와 맞음.
- 의존: T12, T16.

## 5. 결정이 필요한 것

구현 세션이 시작하기 전에 zerolive가 정해 주면 되는 것입니다. 정하지 않으면 괄호 안 기본값으로 갑니다.

1. 새 주소 이름 — `calls` / `settings`로 갈지, `ai` / `admin-settings` 같은 다른 이름으로 갈지. (기본: T6 표대로)
2. 기간 "직접 지정" — 이번에 넣을지. (기본: 넣지 않음, 필요 시 별도 태스크)
3. 배포 단위 — 태스크마다 배포할지, 마일스톤마다 배포할지. 운영 데이터로만 확인할 수 있어 태스크마다가 안전합니다. (기본: 태스크마다)
4. 상태 한 줄 문턱값(T9) — 실패율 5%·3배, 비용 1.5배, p95 2배. (기본: 그대로 두고 운영하며 조정)
5. T17(이상 구간 표시)을 M3에 둘지 뒤로 미룰지. (기본: M3 마지막)
