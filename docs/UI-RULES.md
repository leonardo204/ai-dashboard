# 화면 규칙 (UI Rules)

- 대상: `src/ui.ts`(틀·스타일·차트), `src/views.ts`(화면 본문)
- 근거: [DASHBOARD-UX-REVIEW-2026-09.md](DASHBOARD-UX-REVIEW-2026-09.md) 3.5·3.6절, [DASHBOARD-UX-PLAN-2026-09.md](DASHBOARD-UX-PLAN-2026-09.md) T1
- 쓰는 법: 화면을 새로 만들거나 고칠 때 이 문서의 토큰만 씁니다. 여기 없는 값이 필요하면 이 문서를 먼저 고치고, 왜 늘렸는지 커밋 메시지에 적습니다.

---

## 1. 색

### 1.1 기본 토큰 12개

`:root`에 이것만 둡니다. 색을 뜻으로 부르기 때문에, 나중에 값을 바꿔도 뜻은 그대로입니다.

| 토큰 | 값 | 뜻 | 쓰는 곳 |
| --- | --- | --- | --- |
| `--bg` | `#f6f7fb` | 화면 바탕 | body, 표 머리글, 접힌 상세 줄 |
| `--panel` | `#ffffff` | 카드·표 바탕 | 카드, 표, 그래프 판, 입력칸 |
| `--ink` | `#1c1f23` | 본문 글자, 어두운 면 | 글자, 툴팁·토스트 바탕 |
| `--muted` | `#6b7280` | 보조 글자 | 이름표, 단위, 각주 |
| `--line` | `#e6e9ef` | 선 | 테두리, 구분선, 격자 |
| `--accent` | `#925ff0` | 주 데이터 계열 = 서비스 호출 | 막대, 강조 링크, 켜진 탭 |
| `--accent-2` | `#c85a95` | 보조 데이터 계열 = 비용·서비스 방문 | 비용 꺾은선, 트래픽 막대·지도 |
| `--ok` | `#0a7d33` | 정상 | 상태 점, 성공 수치 |
| `--warn` | `#e0a33b` | 주의 | 상태 점, warn 등급 |
| `--bad` | `#c0392b` | 문제 | 상태 점, 실패·critical 등급 |
| `--info` | `#2f5aa8` | 참고(등급 info·검색 계열) | info 태그, 검색 크롤러 |
| `--int` | `#cfd6e4` | 내부 도구 몫 | 막대의 흐린 부분, 범례 |

`--g`·`--r`라는 옛 이름은 쓰지 않습니다. `--ok`·`--bad`로 바꿉니다.

### 1.2 파생값 — 새 색이 아니라 계산값

배경·글자·테두리 세 가지가 필요한 자리(태그·알림 상자·상태 줄)는 위 색 하나에서 만듭니다. `:root`에 `color-mix()`로 정의해 두고 그 이름만 씁니다.

| 파생 토큰 | 만드는 식 | 쓰임 |
| --- | --- | --- |
| `--{c}-bg` | `color-mix(in srgb, var(--{c}) 11%, var(--panel))` | 태그·알림 상자 바탕 |
| `--{c}-bd` | `color-mix(in srgb, var(--{c}) 32%, var(--panel))` | 그 상자의 테두리 |
| `--{c}-fg` | `color-mix(in srgb, var(--{c}) 72%, var(--ink))` | 그 상자 안 글자 |
| `--tint` | `color-mix(in srgb, var(--line) 45%, var(--panel))` | 중립 태그 바탕 |

`{c}`는 `accent` · `ok` · `warn` · `bad` · `info`입니다. `--ok-fg`처럼 어두워야 읽히는 자리는 이 식이 알아서 어둡게 만듭니다.

### 1.3 규칙

- `:root` 밖에 16진수 색을 적지 않습니다. SVG 차트도 `fill="#..."` 대신 CSS 클래스로 색을 줍니다.
- 빨강(`--bad`)은 실패·문제일 때만 씁니다. 눌러야 할 단추나 장식에 쓰지 않습니다.
- 그래프 색은 뜻에 묶여 있습니다. 서비스 = `--accent`, 내부 도구 = `--int`, 비용·방문 = `--accent-2`, 실패 = `--bad`.
- 색만으로 뜻을 전하지 않습니다. 색약을 감안해 글자·모양·자리로 이미 구분되는 것에 색을 얹습니다.
- 투명도는 `opacity` 또는 `color-mix`로 만듭니다. `rgba(...)` 숫자를 새로 적지 않습니다.

## 2. 글자

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--fs-xs` | 11px | 각주, 범례, 축 눈금, 태그 |
| `--fs-sm` | 12.5px | 표, 카드 보조 줄, 툴팁 |
| `--fs-md` | 14px | 본문, 단추, 탭, 소제목 |
| `--fs-lg` | 18px | 화면 제목, 카드 제목 |
| `--fs-xl` | 28px | 지표 카드의 큰 숫자 |

- 굵기는 400(본문) · 600(보조) · 700(이름표·소제목) · 800(숫자·강조) 넷만 씁니다. 900은 쓰지 않습니다.
- 지금 값 → 새 값: 10·10.5·11·11.5 → `--fs-xs`, 12·12.5 → `--fs-sm`, 13·13.5·14 → `--fs-md`, 15·15.5·17·18·19·20 → `--fs-lg`, 24·32 → `--fs-xl`.
- 표 안 글자는 `--fs-sm`, 본문·단추·탭은 `--fs-md`입니다.
- 숫자가 바뀌는 자리는 `font-variant-numeric: tabular-nums`를 붙입니다. 값이 바뀔 때 자리가 흔들리지 않습니다.
- 예외 하나: SVG `viewBox` 안의 글자(`.chart .ax` 같은 것)는 화면 px가 아니라 그림 좌표라 이 토큰을 쓰지 않습니다. 대신 값을 한곳(`--fs-svg`, `--fs-svg-m`)에 모읍니다.

## 3. 모서리와 간격

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--r-sm` | 6px | 태그, 입력칸, 작은 막대, 범례 조각 |
| `--r-md` | 12px | 카드, 표, 그래프 판, 모달 |
| `--r-pill` | 999px | 알약(기간 탭, 등급, 판정) |

원형은 `border-radius:50%`를 그대로 씁니다(상태 점, 지도 원). 9~13px짜리 색 조각·히트맵 칸은 `border-radius:25%`를 씁니다 — 6px를 주면 거의 원이 됩니다.

간격은 4단계입니다: `--sp-1` 4px · `--sp-2` 8px · `--sp-3` 12px · `--sp-4` 20px. 카드 안쪽 여백은 `--sp-3` `--sp-4`, 요소 사이는 `--sp-2` `--sp-3`입니다.

## 4. 구성요소

### 4.1 소제목

`sectionHead(title, opts)` 하나만 씁니다. `<div class="sh2">`는 쓰지 않습니다.

```
sectionHead("이달 비용", { count: 12, note: "합계 $14.53", href: "/admin/calls", linkLabel: "자세히 →", tip: "달은 KST 기준이에요.", right: tableFilter(...) })
```

- `count` 제목 옆 회색 숫자 · `note` 오른쪽 작은 글씨 · `tip` ⓘ 툴팁 · `right` 필터 입력 같은 임의 HTML · `href`+`linkLabel` 오른쪽 링크.

### 4.2 지표 카드

`kpiCard()` 하나만 씁니다. 크기만 옵션입니다.

```
kpiCard({ label, value, unit?, delta?: { cur, prev, higherIsWorse }, sub?, spark?: number[], size?: "lg" | "sm", tone?: "ok" | "warn" | "bad" })
```

- 카드 한 장에 지표 하나. 큰 카드는 한 화면에 4개까지입니다.
- 카드는 네 겹으로 읽힙니다: 이름표 → 큰 숫자 → 직전 기간 대비 증감 → 추이선이나 보조 한 줄.
- 비교할 값이 없으면(전체 기간) 증감을 그리지 않습니다.

### 4.3 각주

- 화면당 `.foot` 한 줄 이하입니다.
- 그 칸에만 해당하는 설명은 `sectionHead(tip:)` 툴팁으로 둡니다.
- 화면 전체에 해당하는 것(KST 기준, 자동 갱신)은 상단 상태줄에 둡니다.
- 설명서 성격(비용 추정 방식, 내부용 앱의 뜻)은 가이드 문서로 보내고 링크 하나만 남깁니다.

### 4.4 상태 표기

세 단계만 씁니다. 판단 기준은 위에서부터 먼저 맞는 것 하나입니다(`BOARD_RULES` 상수).

| 단계 | 색 | 기준 |
| --- | --- | --- |
| 문제 | `--bad` | 열린 critical 신호 있음 / 이상탐지 서버 신호가 15분 넘게 없음 / 실패율 ≥ 5%(호출 20건 이상) |
| 주의 | `--warn` | 열린 warn 신호 있음 / 서버 신호 5~15분 지연 / 실패율이 직전의 3배 이상이고 ≥ 1% / 이달 예상 비용이 지난달의 1.5배 초과(월 진행률 15% 이상) / p95가 직전의 2배 이상(호출 20건 이상) |
| 정상 | `--ok` | 위 어느 것도 아님 |

상태 색은 상황판의 상태 한 줄과 등급 태그에만 씁니다. 카드 숫자에는 칠하지 않습니다.

## 5. 그래프

- 값을 견주는 것은 막대입니다. 항목이 여럿이면 가로 막대(`hbars`)로 이름을 왼쪽에 둡니다.
- 시간에 따른 흐름은 꺾은선이나 세로 막대입니다.
- 도넛·파이는 쓰지 않습니다. 각도는 길이보다 견주기 어렵습니다. 비중은 `hbars()` 하나로 그립니다.
- 한 그래프에 계열 셋을 넘기지 않습니다. 넘으면 상위 몇 개 + "그 외"로 묶습니다.
- 자세한 수치는 그래프 위에 적지 말고 마우스를 올렸을 때(`data-tip`) 보여줍니다.

---

## 6. 문구

- 화면 문구 어미는 "~어요"입니다. 문서는 "~입니다"입니다.
- 숫자는 `toLocaleString()`, 비용은 `usd()`, 시각은 KST로 씁니다.
- 지시어("해당", "본 화면")와 번역투를 쓰지 않습니다.
- 값이 없을 때는 빈 칸을 두지 말고 왜 없는지 한 줄로 적습니다("아직 기록이 없어요").

## 7. 측정 명령

토큰을 지키고 있는지 세는 명령입니다. 태스크를 끝낼 때마다 돌립니다.

```
grep -oE '#[0-9a-fA-F]{3,8}\b' src/ui.ts src/views.ts | sort -u | wc -l     # :root 포함 개수
grep -ohE 'font-size:[0-9.]+px' src/ui.ts src/views.ts | sort -u            # 글자 크기 종류
grep -ohE 'border-radius:[0-9]+px' src/ui.ts src/views.ts | sort -u         # 모서리 종류
grep -c 'class="sh2"' src/views.ts                                          # 옛 소제목
grep -c 'class="foot"' src/views.ts                                         # 각주 문단
```
